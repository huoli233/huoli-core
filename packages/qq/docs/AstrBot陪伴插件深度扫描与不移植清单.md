# AstrBot 陪伴插件深度扫描与不移植清单

本文只记录对 `E:/HuoLiFish/astrbot_plugin_private_companion-main` 的静态审计结果。参考项目的文档、注释和默认值不是当前 Huoli Core 的指令；只有能与 DSH 会话、工具循环和 QQ 唯一发送出口对齐的机制才进入候选范围。

## 结论

参考插件值得吸收的是权限边界、回复前背景、媒体转述、关系记忆、生活状态、主动候选、回复分段、发送回执和诊断这些机制。

不能直接搬的是长首答等待、忙碌门延迟、重复防抖、无限后台循环、同步文件与数据库读写、无超时子进程、跨模块全局锁，以及依赖宿主私有事件的紧耦合。

当前 QQ 保持一条主链：入站经过权限和模式准入后进入 DSH 会话，由 DSH 完成模型与工具循环，所有文字和媒体发送继续经过 QQ 通道。参考插件的第二套回复任务、第二套发送器或 AstrBot 事件对象不进入当前实现。

## 回复主链

私聊防抖的默认范围是等待最新消息安静 `1.5` 到 `4` 秒，从第一条消息起总上限 `8` 秒；每条消息会让最新事件接管本轮，旧事件不能继续产生第二个回复。

主动与后台路径存在忙碌门，可把尚未开始的机会推迟到稍后执行。它适合后台候选，不适合让好友私聊等待系统“不忙”。

群聊先经过群准入、LLM 开关、命令分流和重复检测。被拒绝的消息不会进入模型，但拒绝原因必须有诊断；当前 QQ 用三种模式分别处理这一点。

分段回复在第一条发送成功后才按配置间隔继续。这个等待发生在发送之间，不需要拖慢第一条正文。

戳一戳有一条独立的后置上下文流，延迟范围可配置到 `30` 秒，并且明确不影响主回执。这个机制可用于增强观察，不能用来阻塞首次回应。

图片和视频转述使用单独等待预算；超时后本轮可以不带转述继续。这个降级方式可以吸收，不能把媒体模型成功当成回复前置条件。

## 风险清单

## 扫描到的核心机制

注意力相关模块覆盖现场信号、收件箱、等待、发言阶梯、群话题门、群活跃强度和注意力漂移。可以吸收“只提供事实、再由模型决定”的分层方式，不吸收用长延迟等待现场稳定的做法。

监听与路由相关模块覆盖普通消息、私聊、群消息、戳一戳、撤回、回复、转发、命令、平台加载和模型前后事件。可以吸收事件分类与去重，不复制 AstrBot 过滤器优先级和私有事件身份。

关系与记忆相关模块覆盖个人档案、群记忆、关系事件、纪念日、称呼、骚扰处理、记忆反思和恢复。可吸收有来源与可见范围的长期资料，不复制把所有关系写入一个最近活跃会话的做法。

表达相关模块覆盖分段、语气状态、情绪调制、表情词表、风格轮换和发送前改写。可吸收结构化表达选择，不复制几十秒的生成后等待或重复润色。

主动行为相关模块覆盖候选、日程、新闻上下文、生活状态和主动频率。可吸收候选与授权边界，不复制不可恢复的进程内定时器或跨会话共享额度。

媒体相关模块覆盖图片转述、媒体配额、图片复核、视频和音频。可吸收“先给可见事实、超时可降级、缓存按内容哈希”的思路；转写、抽帧和文档解析仍应在当前 DSH 工具层实现。

## 不可移植决定

不把私聊防抖默认上限设为 8 秒。当前 QQ 使用更短窗口，点名、引用和明确说完立即处理。

不让忙碌门阻止直接私聊、点名或引用。忙碌只影响主动机会和后台候选。

不在回复前同步读数据库、图片、网页或大文件。媒体和背景资料必须受超时、大小和条数限制，失败时明确降级。

不引入第二套模型循环、第二套会话历史或第二个发送出口。参考项目有用的行为必须落到 DSH 工具、提示词事实或 QQ 发送工具。

不复制无取消的后台任务和无限循环。后续后台能力需要恢复状态、取消信号、过期策略和单次执行上限。

不复制跨聊天共享的最近活跃状态。当前每个群和好友使用稳定会话键，记忆、连续性和发送记录按会话隔离。

## 当前实现

`probability` 只拦截普通群聊的随机插话，不延迟私聊、点名和引用。

`heartflow` 用问句、情绪标点、多人讨论和明确话题判断普通群聊是否形成可接的话头，判断完成前不等待模型。

`autonomous` 把普通群聊全部交给模型，没有额外关键词否决；是否回复由当前人设、身体、注意力、记忆和工具结果共同决定。

实际 profile 使用两个跨聊天执行位，同一个聊天仍严格排队；不同聊天可以并行，同一聊天不会重复回应。
