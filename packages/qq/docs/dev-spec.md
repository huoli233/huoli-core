# 开发规范（执行版）

本文件是 `packages/qq` 下所有改造唯一照做的写法说法：能力该做什么、字段怎么算、状态怎么存，由[自我层规范](self-layer-spec.md)、[生命状态规范](vitals-spec.md)、[记忆系统规范](memory-spec.md)三份能力规范定；代码怎么写、判据怎么落，只由本文件定。

## 适用范围

| 项 | 规定 |
|---|---|
| 生效范围 | `packages/qq` 下全部包，含 `src`、`tests`、包内脚本与包内文档 |
| 不在此列 | 仓库其余包只受根 `AGENTS.md` 约束；任务点名延伸时才适用本文件 |
| 分工 | 本文件只管写法：注释、数值、判断归属、措辞、尺寸、失败、测试、提交、生成物、范围；能力含义不在这里重复 |
| 冲突顺序 | 安全与权限 > 本文件 > 包内既有风格；同一层冲突取更严的一条 |
| 空白处 | 本文件没写的，按根 `AGENTS.md` 与 `packages/AGENTS.md` 执行 |

## 注释

| 规则 | 判据 |
|---|---|
| 注释只用中文，一行说完 | 每处注释是一行、一个句子；出现英文整句注释即不合规 |
| 禁止成块注释与连续两行注释 | 除导出声明那行 `/** … */` 外，`/*` 与相邻两行 `//` 零命中 |
| 每个导出声明上一行有一句中文注释 | `pnpm run verify-export-jsdoc` 为绿；导出条数与紧邻注释条数相等 |
| 注释写为什么、写边界，不复述代码 | 删掉注释后仍能从被注释的那一行逐字读出的信息，不许留在注释里；出现"把 A 赋给 B"这类句子即拒收 |
| 导出 JSDoc 是唯一允许的成块形态 | 正文一句话；关卡要求参数与返回值说明时补标签行，标签行只写必要项 |
| 故意不拦的位置必须写明理由 | 放过校验、吞掉错误、放宽边界的三类位置，注释里有一句说明为什么 |

## 数值与配置

| 规则 | 判据 |
|---|---|
| 数值、阈值、上限、时间窗一律进默认值表 | 同一个数值在源码里只出现在默认值定义处一次；别处只读配置对象 |
| 默认值可被 `Config` 覆盖 | 默认值表每一项在 `Config` 有对应字段；删掉该字段后相关测试必须变红 |
| 代码里不出现裸字面量 | 默认值表、协议常量、测试判断以外的数字字面量零命中 |
| 固定不动的常量要写明原因 | 协议常量、外部规范值、安全不变量旁边有一句"不随配置改"的说明 |
| 默认值只出现一次 | 同一个默认值出现两处即不合规；两份真相迟早对不上 |

默认值表里的字段名、取值与含义归各能力规范；本文件只判"只出现一次"和"可被 `Config` 覆盖"这两件事。

## 判断归模型

| 规则 | 判据 |
|---|---|
| 可见行为只由模型通过工具调用决定 | 代码里没有 `shouldSpeak` 一类的布尔、概率、档位、分数返回值 |
| 禁止用词表、正则、阈值替模型判该不该说 | 出现"该不该发""该不该回""要不要开口""像不像人"的判定分支即不合规 |
| 词表只能用来识别事实 | 词表所在模块的导出注释写明"本模块只产出事实，不产出是否行动"；返回值里没有布尔型结论 |
| 代码里允许的否决只有四类 | 允许的名单与权限、频控与额度、敏感内容与越权工具、安全时段；每类能在代码里枚举出全部条目并各有一条测试 |
| 否决只给理由与下次时间 | 否决分支的返回值只有拒绝原因和下次可用的时刻，不改写内容、不重排、不代说 |
| 状态只进提示词，不许只写不读 | 每个新增状态字段都能渲染成一句进提示词的话；渲染不出就不许加这个字段 |

### 关卡的边界

`qq-proactive` 的 `runGates()` 返回 `{ ok: boolean }`，它回答的是「现在能不能开口」，不是「该不该说」；这一节把上面那条规则的边界钉死，免得两边各读一半。

| 允许的否决 | 落到哪几条 | 判据 |
|---|---|---|
| 允许的名单与权限 | 阶段、停手开关、预授权清单、两把钥匙 | 每类能枚举出全部条目，各有一条拒绝用例 |
| 频控与额度 | 冷却、每天额度、同一正文重复、步数上限 | 拒绝只给码、原因与下次可用时刻，不改内容 |
| 敏感内容与越权工具 | 出站体检、工具允许的名单、一次确认 | 同上 |
| 安全时段 | 静默时段、睡着、刚被吵醒、有人在聊 | 同上；「有人在聊」由收件箱事实填，不许硬编码 |

代码里另有三类**不是否决**的东西，别混进来判：`post_want > addPostWantFrom` 只是「攒不攒候选」的读数门槛，攒住之后发不发仍由模型定；`dropRepeats` 的相似度只用来删重复候选，不产出结论；`replyBudget` 只给这一轮最多几条的上限。三者的返回值都不含「该不该」四个字，也不许被用来替代模型决定。

## 命名与措辞

| 规则 | 判据 |
|---|---|
| 代码、注释、文档、测试数据不出现外部项目名、产品名、人名 | 对包内 `src`、`tests` 与文档按任务点名范围搜一遍，出现即拒收；运行时标识（包名、插件 id）保留，不在此列 |
| 不出现机器路径 | 盘符前缀、`/Users/`、`/home/`、`~/` 一类字符串零命中；路径一律由配置或临时目录给出 |
| 指代用中性说法 | 写"上游实现""既有内核""上一版""参考实现"，并让读者能从同一句里读到被指代对象的可核对属性 |
| 文件名与目录名不带判断、版本、备份含义 | 路径里没有按判断切分的目录名，也没有 `legacy`、`old`、`v1`、`_backup` 这类段 |
| 措辞直说，不用比喻 | 能换成具体名词的泛称就换掉；一句里只讲一件事 |

## 尺寸与结构

| 项 | 上限 | 判据 |
|---|---|---|
| 单文件 | 600 行 | 逐文件统计行数，超一行即不合规 |
| 单包 `src` | 12 个文件 | 清点目录内源文件数；需要例外的包在自己的 `tests/budget.spec.ts` 里写明上限与理由，上限只在那个包里生效 |
| 包级例外 | 生命状态 22 个文件、自我层 24 个文件、装配层 18 个文件 | 状态机、结算、事实源与导出各占一处，拆开比塞进大文件更可读；单文件仍守 600 行，例外数字写在各包自己的 `tests/budget.spec.ts` 里 |
| 相对导入 | 3 层 | 出现四层 `../` 即不合规；跨包一律用包名 |
| 目录深度 | 4 层 | 从 `packages/qq` 起按路径分段计数 |
| 依赖方向 | 单向，无环 | 跨包引用只指向被点名允许的下游；出现环形即不合规 |
| 一个概念一处定义 | 一份实现 | 同一含义出现第二个实现文件即不合规 |
| 更严的目录预算优先 | 取小 | 通用上限与包内目录预算不一致时按更严的一条判 |

## 失败与状态

| 规则 | 判据 |
|---|---|
| 失败返回带 `code`、可读原因、下一步提示 | 每个失败分支都判断三个字段非空，缺一即不合规 |
| `code` 点号分层，人能读的那句是一句话 | 失败码形如 `域.原因`，原因句不超过一行 |
| 工具失败走内核错误通道 | 工具内部不把失败改写成成功；失败结果由内核统一包装 |
| 禁止空 `catch` | 空捕获零命中；必须吞掉的，捕获变量名说明错误来源、紧邻一行注释写明为什么吞、`try` 只包一条语句 |
| 失败文本不得出现对象默认字面量 | 失败文本判断里对象被字符串化的痕迹零出现 |
| 装配失败要当场抛错 | 装配期缺字段、缺依赖、缺引用一律在加载时抛错，不返回空对象、不静默跳过 |
| 状态文件原子写 | 先写同目录临时文件再改名覆盖；任何一次失败都不留半截文件 |
| 状态文件带版本戳 | 文件内有版本字段；结构变化才递增，调参不递增 |
| 读坏可回退 | 正式文件读不出按备份文件、默认值逐级回退，三级都不通才报错，备份不被删除 |
| 一个写者 | 同一状态只有一个写入路径；出现第二个写者即不合规 |

状态文件的字段、写入时机与回退顺序归各能力规范；本文件只判原子写、版本戳、三级回退这三件事是否都在。

## 测试

| 规则 | 判据 |
|---|---|
| 每个包有 `tests/` | 目录存在且至少一条用例；空目录不算 |
| 行为测试优先于单元测试 | 面向可见行为的用例（模型看到什么、用户看到什么、盘上留下什么）占每包一半以上 |
| 负例必须存在 | 每条拒绝、每条失败、每条越界都有会失败的用例；只有正例的包不合规 |
| 测试只写临时目录 | 用例不写包目录、不写用户主目录、不写固定路径；临时目录自建自清 |
| 用例之间互不依赖 | 单跑一条与整套跑结果一致；共享端口、共享临时路径的用例不合规 |
| 判据与实现同刀 | 新增一个行为同时新增对应用例；只加实现不加用例视为未完成 |
| 不为过关卡改判据 | 用例改动只在行为本身变更时出现 |

## 提交与关卡

| 规则 | 判据 |
|---|---|
| 一次提交一件事 | 提交 diff 只覆盖一个任务点；混入无关文件即不合规 |
| 提交信息写做了什么与为什么 | 标题一句写改动内容，正文一段写原因；只写"调整""优化"不合规 |
| 禁止 `--no-verify` | 提交历史里没有绕过钩子的记录 |
| 提交前跑相关包的 `vitest` | `pnpm exec vitest run packages/qq/<包>`；命令与输出贴进回报，退出码非零先处理 |
| 提交前跑相关包的 `oxlint` | `pnpm run lint`，或 `pnpm exec tsx scripts/run-oxlint.ts packages/qq/<包>` 只跑改动包，零 error |
| 提交前跑 `tsc -b tsconfig.host.json` | 类型聚合必须为绿；用别的入口顶替不算 |
| 提交前跑受影响生成器的 `--check` | `pnpm run verify-config-catalog`、`pnpm run verify-tool-catalog`、`pnpm run verify-official-bundle-catalog`，按改动范围全绿 |
| 关卡红不提交 | 任一条非零退出码先处理；处理不了就如实报告，不带红提交 |

## 生成物

| 规则 | 判据 |
|---|---|
| 改 manifest 或描述后必须跑对应生成器 | 配置清单、工具清单、组合清单三者按改动范围各跑一次并全绿 |
| 不许手改生成物 | 生成物文件的改动只来自生成器一次运行；手改会在下一次 `--check` 变红 |
| 生成物与来源同一次提交 | 来源与生成物出现在同一个提交里，分开提交即不合规 |
| 生成器红了先看来源 | 差异指向来源字段或顺序，不改生成物本体 |

## 范围纪律

| 规则 | 判据 |
|---|---|
| 只改任务点名的文件 | diff 里每个文件都能对回任务描述里的一句话 |
| 跨包改动必须说明理由 | 提交信息或回报里逐条写出为什么必须跨包 |
| 范围外的红灯如实报告 | 只记录命令、退出码与输出摘要，不动那个包的文件 |
| 不顺手重构 | diff 里没有与任务无关的改名、重排、格式化 |
| 只读材料不改 | 规范、素材、生成物的内容与时间戳都不变 |
