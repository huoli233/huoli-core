# 三模式与参考插件全机制状态总表

本文把参考插件 `astrbot_plugin_private_companion-main` 的 37 个领域模块、宿主回复链、媒体、记忆、关系、主动、表达、七项原生扩展和管理面，逐项对照当前 Huoli Core QQ 实现。

状态只表示当前 QQ 能否实际使用，不表示参考项目是否存在代码。参考项目的配置页、宿主事件、数据库和发送器不因目录存在就自动算作已接入。

## 状态说明

- 已接入：当前 QQ 主链能实际使用，并有代码或测试依据。
- 半成品：有同类能力或部分接线，但机制、边界、恢复或验收不完整。
- 未接入：当前 QQ 主链没有对应行为，或只有参考项目模块。
- 参考专属：存在代码，但属于 AstrBot 宿主、迁移、页面或可选扩展，不应直接搬入。

## 明确不搬的阻塞机制

| 状态 | 机制 | 原因 |
| --- | --- | --- |
| 未接入 | 8 秒私聊防抖总上限 | 首答过慢；当前改为 2.5 秒上限 |
| 未接入 | 忙碌门延迟好友私聊 | 用户主动找机器人时不等待系统空闲 |
| 未接入 | 6 秒观察防抖作为首答前置 | 只允许后台观察，不阻塞正文 |
| 未接入 | 30 秒戳一戳二次流 | 可以后置增强，不能成为主回应 |
| 未接入 | 同步数据库和文件读取进入回复前 | 会阻塞事件循环 |
| 未接入 | 无超时阻塞子进程进入聊天链 | 无法保证首答预算 |
| 未接入 | 大量 `while True` 后台循环直接复制 | 必须改成可取消、可恢复、可观测任务 |
| 未接入 | 跨聊天全局锁 | 不同聊天应保持独立，同一聊天才需要严格串行 |
| 未接入 | 第二套模型循环与发送器 | 必须继续使用 DSH 会话和 QQ 唯一出口 |

## 结论

当前 QQ 已经接入的是稳定回复主链、会话隔离、短消息合并、注意力事实、记忆、连续性、身体、自我面板、主动候选、图片理解、基础媒体发送、引用与转发、三种互动模式和基本诊断。

当前最大的未完成区块是完整关系系统、个人与群记忆档案例、屏幕与现实设备、视频与音频理解、内容创作、游戏、共同陪伴、直播、完整主动调度、统一存储迁移、七项扩展工作台和第三方扩展 API。

这些缺口不能靠直接复制参考项目完成；每个机制都必须重新落到 DSH Session、工具、附件、任务、权限和面板接口上。
