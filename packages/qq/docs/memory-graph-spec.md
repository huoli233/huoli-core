# 记忆星海规范

本规范定义「她记得的东西怎么变成一张能看的星图」，是 [qq-memory](../qq-memory/README.md) 与 [qq-self](../qq-self/README.md) 面板的验收依据：星点与星链只有一处写入口，图只读；任何判断都不许用关键词，只许用模型报的事实与生命周期事件。

两条铁律写在最前面，后面每一条都从它们推出来。

**铁律一：不许用关键词判断。** 「她是不是高兴、是不是害怕、这件事值不值得记、该不该提起」全部由模型决定，代码只负责存、取、连边与上限。代码里允许存在的是结构与约束——字段、上限、冷却、两把钥匙；不允许存在「遇到某句话就怎样」。

**铁律二：一切由生命周期驱动。** 身体那条线已经有一套完整的时间与状态机，记忆必须挂在同一套事件上，不另起一套；反向也成立：好奇心、想说话、想发动态都从星海里取料。

## 星点

一条记忆就是一个星点。文件 `memories.jsonl`，一行一个，位置由 `Config.file` 指定，缺省为数据根目录下的 `data/memories.jsonl`。

| 字段 | 含义 | 状态 |
|---|---|---|
| `id` | 唯一编号，写入时生成 | 已实现 |
| `text` | 正文 | 已实现 |
| `kind` | 事件 / 印象 / 话题 / 想法 / 身体 | 已实现 |
| `importance` | 重要度 0–100，模型给，代码按上限夹住 | 已实现 |
| `at` | 发生时刻，Unix 毫秒 | 已实现 |
| `layer` | `ephemeral` / `episodic` / `semantic` / `private` | 已实现 |
| `scope` | 属于哪个会话，召回按它过滤 | 已实现 |
| `who` | 相关的人，可为空 | 已实现 |
| `tags` | 话题标签 | 已实现 |
| `vec` | 向量，代码算 | 已实现 |
| `secret` | 这件事不想让人知道 | 待实现 |
| `settled` | 事后平静下来的时刻 | 待实现 |

`secret` 与 `settled` 的用法见 [私密层规范](private-layer-spec.md)。

## 星链

两个星点之间的关系写在 `edges.jsonl`，与记忆文件同目录。一条边只存一次：小号在前，`a < b`。

| 字段 | 含义 |
|---|---|
| `a` / `b` | 两端星点编号 |
| `weight` | 强度，只会涨，上限 `EDGE_DEFAULTS.maxWeight` |
| `why` | 怎么连上的，见下表 |
| `at` | 最后一次加强的时刻 |

`why` 只有五种，全部来自事实，没有一种来自语言判断：

| `why` | 什么时候连 |
|---|---|
| `sameTurn` | 同一次唤醒里写进来的两条 |
| `sameTopic` | 模型写入时明确给了同一条标签 |
| `sameWho` | 指的是同一个人 |
| `sameDay` | 同一场梦、同一次开经、同一天 |
| `recalledTogether` | 一次召回同时返回的两条 |

写入函数是 `linkPoints` 与 `linkTogether`，读是 `edgesOfPoint` 与 `neighboursOf`，都在 `qq-memory/src/edges.ts`。坏行跳过，一条写坏了不该让整份边读不出来。

## 合并与作废

合并只发生在「几乎同文」的情况，权重高的星点**永不合并**，只连长边。

| 情况 | 处理 |
|---|---|
| 内容几乎一样 | 合并成一条，边指向保留的那条 |
| 同一话题但内容不同 | 不合并，加一条 `sameTopic` 边 |
| 事实被新说法取代 | 旧的标 `superseded`，不删；边保留 |
| 超过保留预算 | 丢最老且重要度最低的，不丢 `secret` 与高权重 |

## 召回

现有打分是相似度项加重要度项加新鲜度项，第四项是本规范新增的：

```
score = 相似度项 + 重要度项 + 新鲜度项 + 星链项
星链项 = 与本次已命中星点相连的边权重之和 × 系数
```

这样「想起一件事」会顺带把连着的几件一起带出来，像人。

**召回必须按 `layer` 与 `scope` 双重过滤**：`layer: private` 的星点只在它自己的 `scope` 里可见，任何群聊的召回都不许返回它。现在的实现只按 `scope` 过滤，这一条要补。

## 两层放进

现在是「命中就把正文整段塞进上下文」。改成两层：

- **外层**：只给一句开头一小段，形如「她记得那天很累，因为加班」，给模型一个提示词钩子
- **看全文**：模型需要细节时调 `qq_memory_detail(id)` 拿全文

开头一小段的字数上限是 `Config.skeletonMaxChars`，默认 40；一次最多给 `Config.skeletonMax` 条，默认 6。

## 图接口

面板新增两个只读接口，不开任何写入口。

| 接口 | 返回 | 上限 |
|---|---|---|
| `GET /api/graph?limit=300&since=` | `{ nodes, edges, clusters }` | `limit` 默认 300，最大 4000 |
| `GET /api/graph/node/:id` | 单个星点，含它的边与来源 | 无 |

`clusters` 不落盘，按 `tags` 与边的连通分量现算。

## 前端

页面 `/graph`，画法与参数如下。**不许引第三方渲染库，不许引 WebGL 库**：三维用 Canvas 2D 自己把点画到屏幕上，参考项目 `asdfd3/3d-memory-sea` 已经证明这条路可行。

| 参数 | 默认 | 说明 |
|---|---|---|
| `maxPoints` | 300 | 一页最多多少个点 |
| `maxNeighbors` | 6 | 每点最多连几条线 |
| `minEdgeScore` | 0.15 | 连线的最低分 |
| `timeWindowMs` | 6 小时 | 相邻时间窗内的点更容易连上 |
| `textMax` | 160 | 点文本保留多少字 |
| `hubKeywordMax` | 40 | 关键词出现在这么多个点里就不当连线依据 |

画法要点：星点按星云（`tags` 的第一项）上色，八个星云八种亮色；半径按 `importance`；带外发光；星链按 `weight` 定线宽与透明度；背景深紫到黑渐变。

## 三维画法

用 Canvas 2D 做真三维画法，不引 WebGL。三段算式照参考项目那一套：

1. **布局**：每个星云占球面上的一个方向，用斐波那契球面铺开；簇内的点在自己那一小块球壳里散开，靠 `z` 拉开前后
2. **放到屏幕上**：先按 `yaw` / `pitch` 旋转，再按相机距离做透视，`f = FOCAL / max(140, depth)`；焦距默认 1100，相机默认 `{ yaw: 0.45, pitch: -0.26, dist: 1020 }`
3. **排序**：所有点按 `depth` 从远到近画，远的先画、近的后画，这样才遮得住；点的半径与透明度都乘 `f`

交互：拖动转视角、滚轮推拉、右键或按住 `shift` 平移、悬停看正文。时间滑块只显示该时刻之前的记忆，之后的沉下去变暗。

## 生命周期对应

每一个事件都要在记忆侧留下星点或边，缺一个这条线就是断的。

| 事件 | 出口 | 记忆侧 |
|---|---|---|
| 进食 | `onMeal` | 写「吃了什么」，与同一天同餐连边 |
| 喝水 | `onDrink` | 写「喝了什么」，二十分钟内合并 |
| 梦境 | `onDream` | 写「梦见了什么」，`why: sameDay` |
| 疤痕 | `onScar` | 写「那次极端威胁」，起步高权重，永不合并 |
| 开经 | `onCycleStart` | 写「这一天到了」，与上一次连成周期链 |
| 每天三行 | `qq-self` 的 day | 写「今天」，与当天所有星点连边 |
| 月更 / 月十问 | narrative / probe | 写「这个月」，连到该月高权重星点 |
| 阶段推进 | stage | 写「我变了」，与前一个阶段连边 |
| 辞别 | `farewell` | 写「最后想说的」，最高权重，永不合并 |
| 睡眠 | `sleep_state` | 醒后写「睡了一觉」，与睡前最后一条连边 |
| 想说话 / 想发动态 | `social_hunger` / `post_want` | 只取料，不写新点 |

## 验收

1. 同一次唤醒写两条，`edges.jsonl` 有一条 `sameTurn` 边
2. 召回其中一条时，另一条出现在结果里（星链项生效）
3. `layer: private` 的星点在群聊 `scope` 的召回里**一条都不出现**
4. `/api/graph` 返回 300 条时耗时低于 200ms
5. 空库时 `/graph` 显示「还没有记忆」，不是空白页
6. `qq-vitals` 的每个 `on*` 事件都能在记忆里找到对应星点
