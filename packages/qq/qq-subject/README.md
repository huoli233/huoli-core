# qq-subject

## Summary

自己的状态：心情、精力、无聊、想说话，加上跟谁熟不熟。关系按稳定用户编号保存称呼、别名、关系事件和纪念日，不靠昵称猜人。每轮写成有字数上限的事实段落放进提示词。

## Model Experience

### Prompt content

#### What the model sees

提示词里多一段 `{{qq_self}}`，写清心情、精力、无聊、想说话，以及当前会话的熟悉度。另有一段 `qq:relation`，只给当前私聊对象或当前群发言人：稳定用户编号、当前称呼、最近一次称呼、常用称呼、以前用过的称呼、关系阶段、认识第几天、最近三条关系事件和临近纪念日，并明确说明不拿同名昵称猜成同一个人。关系为空时整段不出现。

##### Relation tools

```markdown
关系工具共五个：`qq_relation_get` 查当前人，群聊要报用户编号；`qq_relation_record` 记真实发生过的关系事件；`qq_relation_name` 设置偏好称呼；`qq_relation_anniversary` 记纪念日；`qq_relation_remove` 删错记的事件或纪念日。事件种类是第一次见面、聊过、约定、冲突、和好、共同经历和普通说明。工具只写事实摘要，不复述聊天原话。
```

#### Token effect

状态段默认最多三百字；关系段默认最多五百二十字，只列最多三条事件和三个临近纪念日。

#### KV Cache effect

状态和关系都放在提示词尾部，内容每轮可能变；稳定身份与规则仍在前面。

## Known Limitations and Deferred Work

- 群聊关系取注意力收件箱里最近的发言人；没有可识别发言人时整段不出现。
- 关系分数按事件变化：聊过、共同经历、约定、冲突与和好分别影响好感、信任和烦躁；一轮有把握的情绪判读也会小幅写回这三项，不必每句话都编成完整事件。高把握、确实冲机器人的判读，只有在原话能从同一说话人的近期消息中核对时才会保存成短期事实；重复原话累计次数，按配置的时间减半并忘掉。下一轮只把仍有效的少量旧印象写成背景，不报数值，也不当面翻旧账。关系默认按 72 小时半衰期向中性回落。模型只看到“有好感、还在防备、最近有点烦”这类感受，不看到内部数值。
- 同一个人反复用短外号叫它时，会按用户、聊天和原话分别记次数。次数默认按 48 小时半衰，七天没再叫就清掉；最近一次称呼优先呈现，常用称呼作为背景，火候只提供当下关系判断，不写死回复方式。
- 纪念日按本地日期提前提示，跨时区部署需要统一运行环境时区。

<a id="dev-note"></a>
### Dev Note

配置项在 `src/index.ts` 的 `Config`：状态文件位置、关系文件位置、主目录覆盖、状态与关系提示字数、每个群的名字、关系熟悉度增量、单次感受写回幅度、情绪事实的半衰期、遗忘时间、保存门槛、容量和提示条数、别名与事件容量、纪念日提前天数。状态默认落在 `data/qq-subject.json`，关系默认落在同目录的 `qq-relations.json`，两份都先写临时文件再改名，关系文件每次覆盖前保留 `.bak`。普通连续发言只在内存累计熟悉度，最多每五秒合并写一次；第一次见人、昵称变化和新群绑定立即落盘。最近活跃群的切换也先改内存，首个会话立即保存，之后连续切群最多每五秒合并写一次。另有十五秒节拍只把脏状态写回，卸载时再强制清一次。

关系仓在 `src/relations.ts`。人按稳定用户编号存；平台昵称只作显示名和别名，同名但编号不同永远是两个人。首次看见一个人会记一条第一次见面事件；昵称变化会记一条普通说明并保留旧称呼。关系事件会分别调整好感、信任和烦躁，并随时间向中性回落；每天维护会统一结算一次，人物互动时也会先结算自己的关系。事件和纪念日都有编号，可删除。提示词关系段在 `src/relations.ts` 的 `renderRelationFacts`，群聊的当前发言人由 `qq-bundle` 从注意力收件箱取。
