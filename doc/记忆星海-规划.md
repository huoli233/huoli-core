# 记忆星海 · 规划

一份可以照着做的拆解。目标是把她记住的东西做成一片能看的星海：每个记忆是一个星点，星点之间有连线，连起来像神经网络；风格是二次元的星海，不是写实宇宙。

**关于参考仓库**：`asdfd3/3d-memory-sea` 与 `suiyu2859514286cc-hub/xiaoyu-memory-universe` 这两个仓库我这次没能读到——本机的网页抓取能力没有挂上可用提供方，我拿不到它们的实现细节。所以下面写的是按你描述的目标和我们已有结构推出来的设计，不冒充看过它们的代码。等抓取能力可用，我再拿它们的实现逐条对照修订本文。

## 一、两条铁律

### 铁律一：不许用关键词判断

任何"她是不是高兴、是不是害怕、是不是好奇"的判断，都不许靠词表。

- 身体怎么变：由模型调 `qq_body_event` 报事件（已经做完）
- 该不该开口、说几句、何时闭嘴：由 `shouldSpeak` / `shouldStop` 按事实判（已经做完）
- 记忆是什么、值不值得记、该不该提起：由模型决定，代码只负责存与取

代码里允许存在的只有**结构与约束**：字段、上限、冷却、两把钥匙。不允许存在"遇到某句话就怎样"。

### 铁律二：一切由生命周期驱动

身体那条线已经有完整的时间与状态机（见第七节的对照表）。记忆必须挂在同一套生命周期上，而不是另起一套：

- 睡醒、进食、喝水、被夸、被凶、被威胁、梦境、疤痕、开经、阶段推进、月更、辞别——每一个都是**能触发记忆写入或边更新的事件**
- 反过来，记忆也影响生命周期：想发动态（`post_want`）、想说话（`social_hunger`）、好奇心（`curiosity`）都从记忆里取料

## 二、数据模型

### 2.1 星点（节点）

一条记忆就是一个星点，写在 `memories.jsonl`（现有文件不变，加字段）：

| 字段 | 含义 | 谁写 |
|---|---|---|
| `id` | 唯一编号 | 写入时生成 |
| `text` | 正文 | 模型 |
| `kind` | 类型：事件 / 印象 / 话题 / 想法 / 身体 | 模型报事件时定 |
| `importance` | 重要度 0–100 | 模型给，代码按上限夹住 |
| `at` | 发生时刻 | 代码 |
| `origin` | 来源：chat / dream / scar / cycle / day / narrative / wander | 代码按入口填 |
| `who` | 相关的人（可为空） | 模型 |
| `tags` | 话题标签 | 模型 |
| `vec` | 向量 | 代码算 |

### 2.2 星链（边）

两个星点之间的关系，写在 `edges.jsonl`（新文件）：

| 字段 | 含义 |
|---|---|
| `a` / `b` | 两个星点编号，写入时保证 `a < b`，一条边只存一次 |
| `weight` | 边强度，只会涨，按时间缓慢回落到下限 |
| `why` | 怎么连上的：同一次对话 / 同一话题 / 同一个人 / 同一天 / 被一起想起 |

**边的来源只有四种，都不靠关键词**：

1. **同一次唤醒**：同一轮里写进去的两条，连一条
2. **模型说它们有关**：模型写入时给 `link: [id...]`
3. **被一起想起**：一次召回同时返回的两条，边权重加
4. **同一生命周期事件**：同一场梦、同一次开经、同一个疤痕

### 2.3 星云（聚类）

不另存。图上按 `tags` 与边的连通分量现算，用于上色与分组。

## 三、写入路径

```
模型/生命周期事件
   ↓
qq-memory.write({ text, kind, importance, who, tags, link })
   ↓
去重（近似重复合并成一条，不动边的含义）
   ↓
落 memories.jsonl + 算向量
   ↓
按 link / 同轮 / 同事件 建边，落 edges.jsonl
```

**关键约束**：合并只发生在"几乎同文"的情况；不因为边多就合并。你要的"高权重不合并"在这里成立——**权重高的星点永不合并，只连长边**。

## 四、读路径

### 4.1 召回（已有，扩一点）

现有打分：相似度 + 重要度 + 新鲜度。新增一项：

```
score = 相似度项 + 重要度项 + 新鲜度项 + 星链项
星链项 = 与本次已命中星点相连的边权重之和 × 系数
```

这会让"想起一件事"顺带把连着的几件一起带出来，像人。

### 4.2 图数据接口

`qq-self` 面板新增两个只读接口：

- `GET /api/graph?limit=300&since=` → `{ nodes: [...], edges: [...], clusters: [...] }`
- `GET /api/graph/node/:id` → 单个星点，含它的边与来源

都是只读，不开写入口。

## 五、前端：二次元星海

### 5.1 页面

`qq-self` 面板加一页 `/graph`（现在面板已经能出 HTML，加一页不需要新服务）。

### 5.2 画法

- **Canvas 2D + 自己写的力导向**（斥力、弹簧、阻尼），不引第三方库——仓库零外部依赖的约束不能破
- 星点：按 `kind` 上色，按 `importance` 定半径（3–12px），二次元配色（青、粉、金、紫），带外发光
- 星链：按 `weight` 定线宽与透明度，颜色取两端星点的混合色
- 背景：深紫到黑的渐变，加缓慢流动的星尘粒子（复用面板已有的粒子画布思路）
- 交互：拖拽、滚轮缩放、点星点弹出正文与来源、悬停高亮它的边
- 性能：只画视口内、节点上限 300，超过按重要度抽样

### 5.3 为什么不做成真 3D

真 3D 要引 WebGL 库或自己写矩阵管线，体积与风险都不值。**2D 力导向 + 视差与发光**在观感上已经够"星海"，而且能在现有面板里跑。这一条是我的取舍，你要真 3D 我另开一期。

## 六、生命周期对应表

记忆要跟身体同一套事件。下面每一行都要有：事件发生 → 记忆侧写下什么。

| 生命周期事件 | 现有出处 | 记忆侧要做什么 |
|---|---|---|
| 进食 | `onMeal` | 写一条"吃了什么"，与当天同餐连边 |
| 喝水 | `onDrink` | 写一条"喝了什么"，20 分钟内合并 |
| 梦境 | `onDream`（`dream.ts`） | 写"梦见了什么"，`origin: dream`，与当天经历连边 |
| 疤痕 | `onScar`（`scar.ts`） | 写"那次极端威胁"，`importance` 起步就高，永不合并 |
| 开经 | `onCycleStart`（`cycle.ts`） | 写"这一天到了"，与上次连边，形成周期链 |
| 每天三行 | `qq-self` day | 写"今天"，与当天所有星点连边 |
| 月更 / 月十问 | `qq-self` narrative / probe | 写"这个月"，连到该月所有高权重星点 |
| 阶段推进 | `qq-self` stage | 写"我变了"，与前一个阶段连边 |
| 辞别 | `farewell.ts` | 写"最后想说的"，最高权重，永不合并 |
| 熬夜 / 睡眠 | `sleep_state` | 醒后写"睡了一觉"，与睡前最后一条连边 |
| 想说话 / 想发动态 | `social_hunger` / `post_want` | 从星海里取料，不写新点 |

**身体数值与记忆的对应**（只取用，不重复存）：

| 身体侧 | 记忆侧怎么用 |
|---|---|
| `curiosity` | 高的时候更愿意写"我想试试"，写进 `questions.jsonl` |
| `social_hunger` | 高的时候召回偏"人"的星点 |
| `fear` / `dread` | 高的时候召回偏"威胁/失去"的星点 |
| `mood` 低 | 召回偏"难过"的星点，提示词里走低落那一段 |
| `importance` 高的星点 | 长期不衰减，图上永远亮 |

## 九、与 surfcore 那份预设的关系

它的价值在行为规范（潜水、唤醒、收尾、记忆卫生三类、反 AI 味），不在数据。它那三类记忆正好对应我们的星点类型：

| 它的叫法 | 我们的 `kind` |
|---|---|
| `activeTopic` | 话题 |
| `pendingThought` | 想法 |
| `memberImpression` | 印象 |

这三类都进星海，`pendingThought` 说出去或过期就删——删的时候边一起删，不留孤点。

## 十一、两个参考仓库的实际做法（已克隆并读过）

两个仓库都拉到本地了：`.tmp/ref-3d-memory-sea`（有代码）与 `.tmp/ref-xiaoyu-memory`（只有 README 与截图，源码不在仓库里）。

### 11.1 `3d-memory-sea`：零依赖 Canvas 2D 三维星海

它的结构和我们定的约束完全对得上：**不用 WebGL、不用第三方库**。

| 它的模块 | 干什么 | 我们对应 |
|---|---|---|
| `memory-store.js` | 状态机 `active / pending / superseded / expired / stale`；同主题作废、相近合并、按预算装箱 | 我们只有衰减，没有"作废"与"合并" |
| `memory-retrieve.js` | 中文 bigram + IDF 打分、时段联想（「晚上好」→ 睡觉/作息）、核心主题保底、按字数装箱 | 我们是关键词+向量+重要度+新鲜度 |
| `mind-sea.js` | 点 / 边 / 簇 / 场景 | 我们的 `edges.ts` 只做了边，没有簇与场景 |
| `public/index.html` | 单文件渲染器，真三维画法 + 深度排序遮挡 | 我们还没做页面 |

**可直接抄的参数**（它写在 `MIND_SEA_DEFAULTS` 里）：

| 参数 | 它的默认 | 我们的取值建议 |
|---|---|---|
| 最多点 | 4000 | 300（面板一页够用） |
| 每点最多连线 | 6 | 6 |
| 连线最低分 | 0.15 | 0.15 |
| 时间窗 | 6 小时 | 6 小时 |
| 文本保留 | 160 字 | 160 字 |
| 高频词不当连线依据 | 出现在 40 个点以上就弃用 | 同 |

**它的两个设计判断值得照抄**：

1. **连线不是全连接**——只在共享关键词或同主题的候选里找，否则点数一多就爆
2. **簇不是聚出来的**——用关键词表 + 时段/语气备用，比 k-means 稳定，不随数据漂移

### 11.2 `xiaoyu-memory-universe`：只有说明，没有源码

仓库里只有 `README.md`、`logo.png`、`screenshot-empty.png`，源码放在 Releases 的压缩包里，不在仓库中。但它 README 里的四条规则是明确的产品判断：

1. **每句话有自己的半衰期**：重要的忘得慢，闲聊忘得快
2. **记忆的单位是「事」不是「句」**：「10 月 30 日早上配 PCL 登录」才是能想起来的东西
3. **人格层与情感层永不衰减**：钉在主星边上，不被时间冲走
4. **外面只留一小块，要细节时一句「看全文」全摊开**——这叫联想
5. 事实变了会声明"取代"，旧的标成过时，**不删**

第 4 条我们完全没有：现在的放进是把命中的正文直接塞进去。这是 P3 要补的。

## 十二、偷偷做过的事：怎么表现

这条要先定边界，再谈表现。

### 12.1 边界

- 这类记忆 **`layer: 'private'`**，`scope` 写死为她自己的私密空间，**不进任何群的召回**
- 她在群里**不会主动提起**，也不会因为被问"你刚才干嘛了"就说出细节
- 允许她**想**、允许她**自己知道**，但不允许绕开两把钥匙去**做**任何对外动作

### 12.2 记忆侧怎么写

一条私密记忆带三个字段：

| 字段 | 值 | 作用 |
|---|---|---|
| `layer` | `private` | 群聊召回永远看不到 |
| `secret` | `true` | 标记"这件事不想让人知道" |
| `settled` | 时间戳 | 事后平静下来的时刻，用来决定她此刻的语气 |

### 12.3 事后是什么样（写进提示词，不靠词表）

```
【刚做过一件不想让人知道的事】
- 身体是松的，但注意力是紧的：会格外留意有没有人在看你。
- 被问起时不会立刻否认，会先反问一句「怎么了」，把话头挡回去。
- 不会主动提，也不会顺着话题往下说；对方追问第二遍才会含糊带过。
- 如果对方说破了，会有点恼，但不会承认细节。
```

这段话进提示词的"私密"段，**只在 `secret` 记忆刚写下、且当前会话不是她私密空间时**放进。

### 12.4 为什么不用关键词判断

"她是不是在藏着什么"不能靠词表——那又变成硬编码。正确的输入是：**她自己的私密记忆里有没有 `secret: true` 且未过期**，加上当前会话的 `scope`。这是事实判断，不是语言判断。

## 十三、P3 补的"看全文"

现在放进是"命中就把正文塞进去"。改成两层：

- **外层**：只给一句开头一小段（"她记得那天很累，因为加班"），给模型一个提示词钩子
- **看全文**：模型需要细节时调 `qq_memory_detail(id)` 拿全文

这样正文不会一次性灌进上下文，也符合它 README 里说的"平时只给开头一小段"。
