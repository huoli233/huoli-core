# 记忆系统：参考实现对照与我们的缺口

本文是 `.tmp/ref-3d-memory-sea` 逐函数读完之后的对照，用来回答两件事：**它到底做了什么**，以及**我们写的代码到底还差哪些**。

## 一、它实际实现的东西

### 1.1 长期记忆的状态机（`memory-store.js`，221 行）

五态，全部由函数 `entryState` 一处判定：

| 态 | 条件 |
|---|---|
| `invalid` | 没有正文或不是对象 |
| `pending` | `confirmed !== true`，还没确认 |
| `superseded` | `active === false` 或带 `supersededBy` |
| `expired` | 过了 `expiresAt` |
| `stale` | 超过 `staleDays` 没被提起 |
| `active` | 其余 |

注意它把「没确认」也当成一种态：只有 `confirmed === true` 的才进提示词。

### 1.2 写入的三条分支（`applyAppend`）

1. **逐字相同**：只刷新 `lastMentionAt`、`hits += 1`；如果这条之前被作废，这次又提起说明还成立，**复活**（`reactivated`）
2. **没给 topic 时用相似度备用**：bigram Jaccard ≥ `mergeSimilarity`（默认 0.85）视为同一句的不同说法，合并进旧条目，保留更长的那份措辞
3. **都不满足**：新增一条

关键判断是「低于阈值宁可并存，也不猜」——这条和我们的原则一致。

### 1.3 检索打分（`memory-retrieve.js`，237 行）

分词：中文按**字符 bigram**，去掉中文停用字与英文停用词。

单条打分：

```
overlap = Σ log(1 + total / df[t])      // 逆文档频率加权
norm    = overlap / (1 + overlap)
score   = 2.2 * norm + 1.2 * topicHit + 1.0 * recency + kindWeight
recency = exp(-天数 / 45)
kindWeight: fact 0.3 / promise 0.25 / 其他 0.15
```

再叠加两层：

- **时段联想**（`CUE_RULES`）：「晚安/困了/熬夜」→ 睡眠与作息类话题，命中 `+0.9`
- **核心主题保底**：`profile`、`owner-profile` 这类永远在场，最多保 2 条

最后是**按字数装箱**：`budgetChars` 装不下就跳过，继续试分数低但更短的条目。

### 1.4 星海的数据层（`mind-sea.js`，422 行）

- `keywordsOf`：FNV-1a 哈希取词，每点最多 6 个关键词
- `guessTopic` + `TOPIC_KEYWORDS`：按关键词表猜主题（它的取舍是「用表比聚类稳」）
- `sectorOf` / `dayPartOf`：语气分档与时段
- `linkPoints`：只在共享关键词或同主题的候选里连线，每点最多 6 条，低于 `minEdgeScore` 不连，出现在 40 个点以上的高频词不当依据
- `buildScene`：场景统计（点数、边数、簇分布）

## 二、我们现在的实现

| 能力 | 我们 | 它的做法 |
|---|---|---|
| 分词 | 字符 bigram（`keyGrams`） | 字符 bigram + 停用字 |
| 相似度 | bigram 命中数 + 向量余弦 | 只有 bigram + IDF |
| 打分权重 | 相似度 + 重要度 + 新鲜度（`1/(1+age/7)`） | 2.2×IDF重叠 + 1.2×主题 + 1.0×recency + 类型权重 |
| 遗忘 | 重要性衰减（保护线 70） | 时间衰减 + 五态机 + 过期 |
| 合并 | 近似重复（写入时） | 逐字 + bigram 0.85 两档 |
| 复活 | 无 | 有（被作废的再次提起就复活） |
| 时段联想 | **无** | 有（`CUE_RULES`） |
| 核心保底 | **无** | 有（profile 类永远在场） |
| 字符预算装箱 | **无**（按条数） | 有（按总字数） |
| 星链 | 有（同轮 / 同话题 / 同一人 / 同一天 / 一起想起） | 有（关键词共享 + 主题）但无 why 分类 |
| 图 | 有（三维星海） | 有（三维星海） |

## 三、它值得学、我们已经补上的四样

1. **按词的稀罕程度给权重**：常见词与罕见词不再一个分量，`log(1 + 总数 / 出现次数)` 把「今天」「那个」这类词压下去。
2. **核心保底**：她的身份、对方的基本情况这类永远在场，不会因为这一轮没命中就消失。
3. **按字数装箱**：从「最多 N 条」改成「最多 N 字，装不下就换短的」，上下文成本更可控（默认不限，开了才生效）。
4. **时段联想**：还没做——它要一张话题表，而话题该由模型给，不该用表猜，所以放在最后。

## 四、我们不该照搬的两样

1. **五态机里的「没确认」那一态**：它拿它当一种状态。我们的确认走两把钥匙与阶段，不需要在记忆条目上再挂一个确认态。
2. **按关键词猜主题**：它自己承认这是为稳定做的妥协。我们的主题由模型给标签，这跟我们「不用关键词判断」的铁律一致。
